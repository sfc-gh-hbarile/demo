TellThe problem

Finance spends close week finding the answer, not acting on it

Acme Corp has three regions and three product lines. Q3 is closed, and Q4 is forecast in two versions. Something went wrong in EMEA, and leadership wants the why, the outlook, and a review package before the forecast meeting.

What FP&A does today

  • Pulls actuals and plan into spreadsheets to rebuild variance by hand
  • Hunts through email and decks for why the forecast changed
  • Rebuilds scenario math each time someone asks "what if"
  • Chases budget owners for sign-off over email

The story hidden in the data

  • EMEA, from July: Core Platform price -6% (competitive discounting)
  • EMEA Advisory Services: unit cost +12% (contractor rates)
  • EMEA opex +3% (backfill)
  • APAC Data Products price +3%
  • North America on plan

What the agent has to do

  • Find the variance and split it into price, volume, and cost
  • Explain what changed between forecast FY26_AUG and FY26_SEP, and why
  • Run a scenario on approved logic, not improvised math
  • Quote the documented assumptions
  • Prepare a review package that a person must approve
Say: "Everything you'll see runs on governed data in Snowflake. The agent doesn't guess: each number comes from an approved metric or an approved procedure, and you can see which one."

How the number was validated

  • Rates: billed credits per million tokens (3.25 input, 16.26 output, 4.07 cache write, 0.33 cache read) match the Service Consumption Table, Table 6(d)
  • Bill: per-request credits (4.059) equal the CORTEX_AGENTS line in METERING_DAILY_HISTORY (4.059)

  • Levers: pin a smaller orchestration model, keep instructions and tool descriptions lean, and reuse threads for follow-up questions
The resource monitor caps warehouse credits only. Use a Snowflake budget to cap AI spend.
TellWhat you saw

Answers finance can trust, with finance still in control

The same governed layer answered five different kinds of question, and the agent showed where every answer came from.

Governed numbers

Every metric comes from one semantic view. The agent's SQL can be inspected, and dashboards reuse the same definitions.

Approved logic

Scenarios run in a procedure finance owns. The model chooses the inputs; it never invents the formula.

Grounded reasons

"Why" answers cite the forecast note or the planning document. The skill tells the agent to say so when no source supports a reason.

Human in the loop

The agent can prepare a package but can't release it. Approval is a separate, audited step.

From "find the number" to "decide what to do about it", in one conversation.

Appendix B: presenter checklist

Before, during, and after the demo

Before (5 minutes)

  • Log in as FPA_DEMO_USER (role FPA_DEMO_ROLE)
  • CALL FPA_DEMO.FPA.RESET_DEMO_WORKFLOW();
  • Open the FP&A Assistant and a worksheet side by side
  • Optional: START_COST_RUN('demo_name','DEMO_SESSION')
  • Ask Q1 once beforehand to warm the warehouse

During (15 to 20 minutes)

  • Tell: slides 2 and 3 (3 minutes)
  • Show: Q1 to Q4 in one chat; open the SQL behind Q1
  • Show: Q5 in a new chat, then the status view, approve, and the status view again
  • Show: the Cost Estimator; change users and $/credit live
  • Tell: slides 9 to 11 (5 minutes)

After and troubleshooting

  • END_COST_RUN('<run_id>'); check V_RUN_COSTS a few hours later
  • Reset the workflow for the next presenter
  • No package created? Use a new chat
  • Approval says NOT_FOUND? Use the exact ID, and don't reset between submit and approve
  • Cost questions? AI Credits ($2.00) and Platform Credits ($3.00) are priced separately; see slide 8
  • Dashboard can't read views? The role needs USAGE_VIEWER and GOVERNANCE_VIEWER
